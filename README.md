# Steam Roll · 今天玩什么

一个运行在本机的 Steam 游戏推荐小工具：按 Steam 分组浏览游戏，用筛选条件或手选候选池，随机决定下一款想玩的游戏。

## 一键使用

双击 **`启动 Steam Roll.cmd`**。脚本会启动后台服务并打开 `http://127.0.0.1:17863`。

- 需要 Windows 和 Python 3.10 或更新版本。本机已验证 Python 3.13。
- 日常使用不需要 npm、第三方 Python 包、Steam API Key 或公开个人资料。
- 重复运行会复用当前项目的服务并打开网页，不重复启动进程。
- 若端口被别的应用占用，会显示错误，不会结束别人的进程。
- 网页关闭后服务仍在后台。点击网页左下角“退出本地服务”，或双击 **`停止 Steam Roll.cmd`**，即可退出。
- Steam 可以保持运行。游戏、分组或隐藏状态有变化后，点击右上角“刷新”。

## 选择下一款游戏

1. 左侧可多选 Steam 分组；多组选并集。游戏同时属于多个分组时，可以在各组看到，但抽取池只计一次。
2. 可叠加搜索、已安装/未安装、游玩时长、最近游玩条件；这些条件取交集。
3. 使用“从筛选结果抽取”，或者点击封面勾选几款，再切换“从手选游戏抽取”。手选模式也遵守当前分组和筛选条件，候选数会明确显示。
4. 点击 **ROLL 一个游戏**。每款候选等概率；默认本轮不重复。抽完后可重置本轮，也可关闭不重复。

支持名称、最近游玩、时长排序，分组折叠，分批显示大分组，抽取结果与本次会话历史。选择、筛选、历史不写入 Steam，也不持久保存。

封面优先读取本机 Steam 缓存，兼容旧文件名、中文封面、新版哈希子目录和自定义封面。没有缓存时显示占位卡片；可勾选 **“联网补全封面”** 从 Steam 官方 CDN 读取缺失图片，默认关闭。联网时只请求可见游戏的图片，不上传分组或游玩记录。

## 只读边界

- 服务只监听 `127.0.0.1`，校验 Host / Origin，不开放跨站访问。
- Steam 文件统一以 `rb` 打开；不写分组、不改隐藏状态、不改游玩时间、不启动 Steam 或游戏。
- 服务启动后安装 Python audit hook，拒绝所有文件写入、删除、重命名、目录创建、注册表修改和子进程启动。并非只靠界面约定；测试会实际尝试这些操作并验证被拒绝。
- 不加载 Steam 数据库驱动，不调用会产生锁文件或恢复日志的数据库打开方式。
- 新旧隐藏列表合并排除，隐藏 App ID 不进入公开游戏列表，也无法通过封面接口读取。若分组缓存损坏或无法验证隐藏列表，停止读取，界面清空旧结果。
- 写入范围仅限启动器自己的 `.runtime/` 日志，以及浏览器自身的缓存。服务进程不向文件系统写数据，不修改 Steam 的文件权限。

该保护是应用进程内的防误写约束，不是防恶意原生代码的操作系统沙箱。项目没有原生扩展或第三方运行时依赖。

## 数据来源与已知限制

| 内容 | 本机来源 |
| --- | --- |
| Steam 位置、当前账号 | Windows 注册表，只读访问 |
| 账号显示名 | `config/loginusers.vdf` |
| 隐藏、分组 | `userdata/<账号>/config/cloudstorage/cloud-storage-namespace-1.json` 和待同步文件；兼容 `7/remote/sharedconfig.vdf` |
| 游玩时长、最近游玩 | `userdata/<账号>/config/localconfig.vdf` |
| 名称、游戏类型 | `appcache/appinfo.vdf`，支持 v39/v40/v41 |
| 安装状态 | 各游戏库的 `appmanifest_*.acf`，要求完整安装标志及实际安装目录 |
| 封面 | `appcache/librarycache`、账号 `config/grid` |

这里是**本机缓存游戏列表**，不是在线授权清单：合并当前账号的本地游玩记录、分组成员及归属该账号的安装清单。历史玩过但已失去授权的游戏仍可能存在；从未同步到本机、没有游玩或分组记录的游戏可能缺失。不会把全局 `appinfo` 中仅浏览过商店的所有游戏当作已拥有游戏，也不会导入其他账号独有的安装清单。

默认展示 `Game` 和 `Demo`，排除 DLC、工具、软件、原声等非游戏项目。缺少可靠类型信息的条目暂不加入，并显示提示。游玩时长单位是分钟；无最近运行时间明确显示“暂无记录”，不会当作“很久没玩”。账号之间独立读取，可以在右上角切换。

普通 Steam 分组按本地记录还原。动态分组目前只展示显式缓存的成员，未实现 Steam 的全部动态筛选规则，会显示提示。本机已验证的当前分组均为普通分组。离线库盘不可访问时显示提示，其中游戏不标为已安装。

## 配置与开发验证

自动检测失败时，可在 PowerShell 中指定 Steam 目录后启动：

```powershell
$env:STEAM_ROLL_STEAM_PATH = 'D:\Program Files (x86)\Steam'
.\launch.ps1
```

也可手动运行 `python -B app.py --steam-path "D:\Program Files (x86)\Steam" --port 17863`。更换端口使用 `launch.ps1 -Port 17865`，停止时使用同一个 `-Port`。

```powershell
# 后端与只读边界测试：使用临时测试数据
python -B -m unittest discover -s tests -p 'test_*.py' -v

# 开发测试工具；日常使用无需安装
npm ci
npm test

# 先启动服务，再验证真实网页与真实数据
.\launch.ps1 -NoBrowser
npm run test:browser
python -B tests/live_check.py
python -B tests/launcher_check.py
.\launch.ps1 -Stop
```

浏览器测试使用本机 Microsoft Edge 的无界面实例，截图和报告放在 `artifacts/`。真实数据校验对读取的 Steam 配置及安装清单进行前后 SHA-256 比较；不会运行游戏。

参考工具及实现取舍见 [调研记录](docs/research.md)。
